# MVP 기능 명세 — Welfare Next

## 문제 / 사용자 / 핵심 가치
- 문제: 복지정책에서 탈락한 뒤 사용자가 탈락 원인과 다음 선택지를 스스로 다시 해석·탐색해야 한다.
- 사용자: 복지정책 신청 후 탈락 통보를 받은 사람.
- 핵심 가치: 탈락을 서비스 여정의 끝이 아니라 다음 지원으로 이어지는 출발점으로 바꾼다.
- 핵심 사용자 행동: 탈락 정보와 조건 입력 → AI 분석 → 대안 정책과 다음 행동 확인.

## P0 기능 목록

### F-01 탈락 사유 쉬운 말 설명
- 목적: 행정적인 탈락 문구를 사용자가 이해할 수 있는 표현으로 바꾼다.
- 입력: 신청 정책명, 탈락 사유 문구
- 처리: Microsoft Copilot SDK를 이용해 핵심 탈락 조건과 의미를 구조화하고 쉬운 한국어 설명 생성
- 출력: 한 줄 요약, 상세 설명, 부족/초과한 조건 항목
- API/DB 의존성: AI 분석 API. 저장은 MVP에서 필수 아님.
- 실패 시: 원문을 유지하고 'AI 설명을 불러오지 못했습니다'와 재시도 제공
- 담당: Client 수인 / AI·Server 연동 민준과 협업
- 인수 조건:
  - Given 탈락 사유가 입력됨 / When 분석 요청 / Then 쉬운 설명이 표시된다.
  - Given 필수 입력이 비어 있음 / When 제출 / Then API를 호출하지 않고 입력 오류를 표시한다.
  - Given AI API 실패 / When 응답 실패 / Then 입력값을 유지하고 재시도할 수 있다.

### F-02 대체 복지정책 추천 및 자격 비교
- 목적: 현재 사용자 조건으로 검토 가능한 다른 지원정책을 보여준다.
- 입력: 연령, 소득 관련 정보, 가구형태, 거주지역 등 MVP에서 확정한 조건
- 처리: 사용자 조건과 정책 조건을 비교하고 후보별 적합/확인 필요 항목을 정리
- 출력: 추천 정책 목록, 추천 이유, 자격조건 비교
- API/DB 의존성: 실제 정책 데이터 또는 대회용으로 명확히 표시된 데이터셋 필요
- 실패 시: 추천 결과가 없으면 조건을 바꾸어 다시 확인하도록 안내
- 인수 조건:
  - Given 사용자 조건이 입력됨 / When 추천 요청 / Then 정책별 추천 이유가 표시된다.
  - Given 후보가 없음 / When 분석 완료 / Then 빈 화면 대신 Empty 상태와 재검색 행동을 제공한다.
  - Given 정책 데이터가 불완전함 / When 결과 표시 / Then 확인이 필요한 조건을 확정 정보처럼 표현하지 않는다.

### F-03 다음 행동 안내
- 목적: 추천 결과를 실제 행동으로 이어준다.
- 입력: 탈락 분석 결과, 추천 정책 및 사용자 조건
- 처리: 재신청, 추가서류 확인, 이의신청 검토, 대체 정책 신청 등 가능한 다음 행동을 정리
- 출력: 우선순위가 있는 다음 행동 카드와 준비할 내용
- API/DB 의존성: 정책별 후속 절차 데이터가 있을 경우 사용
- 실패 시: 근거가 없는 절차는 생성하지 않고 '공식 안내 확인 필요'로 표시
- 인수 조건:
  - Given 분석 결과가 존재 / When 결과 화면 표시 / Then 최소 하나의 다음 행동 영역이 존재한다.
  - Given 절차 정보가 미확인 / When 안내 / Then 확정적인 신청 절차로 단정하지 않는다.

## P1 / P2
- P1: 여러 대안 정책을 단계적으로 잇는 복지 경로 시각화
- P1: 결과 공유/저장
- P2: 정책 즐겨찾기 및 과거 분석 기록

## 이번에 만들지 않을 기능
로그인/JWT/OAuth, 결제, 알림, 관리자 페이지, 자체 ML 추천모델 학습, 불필요한 복잡한 권한 체계.

## 1분 시연 순서
1. '주거지원 신청에서 소득기준 때문에 탈락' 사례 입력
2. AI가 탈락 사유를 쉬운 말로 설명
3. 연령·가구·소득·거주지역 조건 확인
4. 대체 정책 후보와 자격조건 비교 표시
5. 다음 행동 카드 확인

## 구현 리스크 / 대체 플랜
- 실제 정책 API 미확정: 검증된 정적 정책 데이터셋으로 MVP를 구성하고 Mock/샘플임을 명확히 표시
- AI 응답 지연: 로딩 상태와 재시도 제공
- 추천의 확정성 위험: '신청 가능 확정'보다 '조건상 검토 가능한 정책'으로 표현
