# User Flow — Welfare Next

## 대표 사용자 / JTBD
복지정책에서 탈락한 사용자가 '왜 안 됐는지' 이해하고, 지금 조건에서 무엇을 다음으로 알아봐야 하는지 빠르게 확인한다.

## 정상 흐름 (Happy Path)
1. [SCR-01] 첫 화면에서 서비스 가치 확인 후 '탈락 결과 분석하기' 선택
2. [SCR-01] 신청했던 정책과 탈락 사유 입력
3. [SCR-01] 연령·가구형태·소득 관련 정보·거주지역 입력 및 클라이언트 검증
4. [SCR-01] 분석 요청 → Loading 상태 → 분석 API 호출
5. [SCR-02] 탈락 사유 쉬운 설명 확인
6. [SCR-02] 추천 정책 후보와 현재 조건 대비 자격조건 확인
7. [SCR-02] 재신청/추가서류/이의신청/다른 정책 검토 등 다음 행동 확인
8. [SCR-02] '조건 수정해서 다시 찾기'로 입력 화면 복귀 가능

## 분기 / 예외 흐름
| 발생 지점 | 사용자에게 보여줄 내용 | 복구 행동 |
|---|---|---|
| 필수 입력 누락 | 누락된 필드 아래 오류 문구 | 해당 값 입력 |
| 분석 API 지연 | '조건을 확인하고 있어요' Loading | 중복 제출 방지 |
| API 실패 | 분석을 불러오지 못했다는 국소 오류 | 다시 시도 |
| 추천 결과 없음 | 현재 입력으로 찾은 후보가 없다는 안내 | 조건 수정 |
| 정책 조건 미확인 | 공식 확인이 필요함을 명시 | 정책 상세/공식 정보 확인 |
| 뒤로가기 | 기존 입력 보존 | 수정 후 재분석 |

## 상태 전이표
| 화면 ID | 행동 | API | 성공 시 | 실패 시 |
|---|---|---|---|---|
| SCR-01 | 분석 제출 | POST /api/welfare/analyze | SCR-02 | Error 상태 |
| SCR-02 | 다시 분석 | 없음 또는 재호출 | SCR-01 | 기존 결과 유지 |

## 데모용 30초 사용자 여정
'주거지원에서 소득기준 때문에 탈락했어요' 입력 → 사용자 조건 선택 → 분석 → 쉬운 탈락 설명 → 대체 정책 카드 → '다음에 할 일' 확인.
